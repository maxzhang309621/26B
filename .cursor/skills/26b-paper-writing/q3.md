## 模型建立

### 本段任务

把黑盒仿真上的搜索—定位—清除写成两层模型：**覆盖层（听全）** + **服务层（调用问题一、二清除）**。允许先写一个虚拟时间最小化的规划形态，但必须声明：源位置未知、接口为四条 POST，故该规划不能开环求解。

### 段落顺序

1. **转化句。** 问题三是未知全向源（10–16 个，频道 1–20）的在线搜索清除。决策是听点、频道、第二/第三站与清除点；观测只有 `direction` / `near` / `no_signal` 与清除成败。
2. **目标。** 最小化虚拟时间
   \[
   T=\frac{L}{5}+N_{\mathrm{sw}}\cdot 1+N_{\mathrm{det}}\cdot 5+N_{\mathrm{fail}}\cdot 3+N_{\mathrm{ok}}\cdot 5,
   \]
   单位秒；\(L\) 为折线长（m），速度 \(5\,\mathrm{m/s}\)。硬约束：不得漏清已存在源；协议合法。
3. **覆盖层。** 最坏 \(r_{\mathrm{eff}}=1000\,\mathrm{m}\)，工作圆半径 \(1800\,\mathrm{m}\)。听全 \(\Leftrightarrow\) 圆盘上每点到最近听点距离 \(\le 1000\,\mathrm{m}\)。圆盘覆盖：单位圆 \(r(7)=1/2<1000/1800\)，故「原点 + 环上正多边形」完备。当前默认：原点 + 半径 \(1150\,\mathrm{m}\)、相位 \(10^\circ\) 的正六边形（`q3_waypoints`）。用解析证书 `q3_coverage_certificate` 报告环带最坏最近距离（方法卡曾记 \(988.51\,\mathrm{m}\)，余量约 \(11.5\,\mathrm{m}\)——**引用前重跑证书**）。对照：\(8\times 1200\) 最坏约 \(828\,\mathrm{m}\)（F1(c)）；五点 \(1200\,\mathrm{m}\) 不能覆盖。
4. **服务层。** 每频道可行域即问题一的 \(R\)。`can_clear_20` 则在 \(c_{\mathrm{SEC}}\) 清除；否则问题二给出 \(S_2\)。频道：原点 \(1\to 20\) 全扫，之后只扫未发现频道；定位期间锁频道。`near`（\(\le 5\,\mathrm{m}\)）当场清除。
5. **相位结构（与默认策略一致）。** **先搜后清**：覆盖期除 `near` 外不离开航路去清；听点走完后对 pending 源做批量清除。停搜：已听 + 待清 \(\ge n\)（或覆盖完成）。不要把「听完即清」写成当前主模型。
6. **时间账本（建立里定义，结果里填数）。** 移动拆为骨干扫描 / 回接 / 定位行驶 / 清除绕行，四者之和等于 `travel_s`。

### 必须引用

问题一公式（\(R\)、\(r_{\mathrm{SEC}}\)、\(\delta=1.01^\circ\)）、问题二候选带与 `next_stations`。写明：定位子程序不得另写一套沿示向爬行。

## 模型求解

### 选定算法

构造性策略，三块：

1. **等圆覆盖航路**（Kershner 型圆盘覆盖的规则分解，不是栅格割草机）。
2. **序贯交会**：每次新示向调用问题一；不能清则问题二。
3. **清除序**：覆盖结束后，滚动时域开放 TSP（RH-OTSP）：对 pending 的估计服务点，\(n\le 12\) 用 Held–Karp 开放路，否则 NN+2-opt；走一条前缀（约 \(280\,\mathrm{m}\) 或到达则动作）后按新位姿重解；滞回 \(50\,\mathrm{m}\)。协议无空驶，前缀必须落在 `/measure` 或 `/clear`。

兜底：交会空/无界/数值退化时有界爬行，每频道最多 40 步 \(\times 12\,\mathrm{m}\)；正常路径应报告 creep 次数为 0。

### 步骤模板（与 `HuntPolicy` 默认 batch 对齐）

**Step 1** `/enter`；读 `jammer_count` 作 \(n\)（缺省按 16）。  
**Step 2** 原点全扫 20 频道；`near` 立即清。  
**Step 3** 按六边形听点巡游；每点只测尚未排除的频道。听到则记 pending，**不**在覆盖期 `_drain_pending`（除 near）。  
**Step 4** 听点数满或已听 \(\ge n\)：覆盖结束。  
**Step 5** `_batch_clear_by_path`：估计点（两站且 `can_clear_20` 用包围圆心，否则问题二推荐点）→ 开放路排序 → 滚动执行定位/清除。  
**Step 6** 交会过大则圆心附近扇形补清，再专用第二站。  
**Step 7** `/exit`。真实时间看门：`remaining_real_duration_s` 减预留，禁止写死 1200。

配图：F1(a) 航路；一张「覆盖 / 定位清除」状态机（半页）。路径对比 GIF 若展示 defer vs batch，必须标明哪条是提交版。

### 求解理由

环境黑盒、源未知、点数极少；覆盖可解析证明，服务层把在线信息交给问题一、二，避免开环轨迹。滚动重解是因为第二站依赖当前位姿（`next_stations(now=·)`）。

## 结果分析

### 必须报告（分清数据源）

1. **官方演练**（主成绩）：全清局数、均 \(T_v\)、秒/源。只引用 `output/baselines.md` 当前 Q3 行，并写清局数。历史锁（如 5000.8 s、4714.4 s）若引用必须标明批次名，不得与当前基线混成同一个「本文结果」。
2. **时间构成**：行驶 / 检测 / 换频 / 成功清除 / 失败清除占比。解释：行驶主导，故交会优先主要减测次；总时间下界仍受覆盖折线约束。
3. **动作结构**：方向测量次数、顺路复测命中率（若该批次有）、creep 是否为 0、clear miss。
4. **mock 对照**：多种子全清率 = 1 只能作为正确性，不能替代演练时间。

### 解释句

- 源数增加时单源耗时下降（覆盖是固定成本）——若 F4(b) 仍支持该相关，核对自己用的那批 JSON。
- 先搜后清减少折返，代价是覆盖期末尾才开始清；用账本里 `clear_detour` 与 `rejoin` 说话，不要空喊「更优」。

## 模型验证

验证类型 = **覆盖证书 + mock 全清 + 演练个数一致 + 几何核回灌**。不要做无依据的参数大扰动。

### 分层写

1. **覆盖。** 解析最坏距离 \(\le 1000\,\mathrm{m}\)；五点反例不能覆盖。证书函数 `q3_coverage_certificate`。
2. **定位核。** 第二次 `direction` 后先 `locate_quality` 再决定是否再测；单测禁止「直接爬行」为常规路径。
3. **闭环。** mock 固定种子 10–16 源全清、pending=0、非法动作=0、`/exit` accepted。边界 16 源全清。
4. **演练。** 程序清除数 = 官方结束界面个数；只报演练。
5. **反演。** 有真值包含率 1；无真值只一致性。
6. **失败对照。** 未采用的六点若曾均时上升、Step 8 插入变慢，用一行说明「正确但不更快」，体现验证否决了候选。
